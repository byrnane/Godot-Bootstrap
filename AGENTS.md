# Работа с шаблоном Godot

Цель проекта — универсальный шаблон разработки игр на Godot в `main` и
специализированные шаблоны для 2D, 2D PixelArt и 3D на его основе.
Конкретные игры развиваются в отдельных репозиториях.

## Ветки и границы

- Основное ядро и основную разработку веди в `main`. Это единственный источник
  общих систем, сервисов, UI-поведения, контрактов и инструментов сопровождения.
- `2d`, `2d-pixelart`, `3d` зависят непосредственно от `main`. В них развивай
  только специфику соответствующего шаблона: собственные игровые системы и фичи,
  контент, представление, настройки, сцены, ресурсы и дополнительные аддоны.
  Общие улучшения сначала вноси в `main`, затем переноси во все варианты.
- Работай в основной папке, переключая ветки обычным `git switch`.
  Дополнительные worktree и изменения расположения проекта, запуска или
  привычного процесса сначала согласуй с владельцем и объясни последствия.
- Все три варианта должны содержать актуальную закоммиченную базу `main`.
  Перед разработкой специфики обновляй ее ветку из `main`; задачу с изменениями
  в `main` завершай переносом этих изменений во все три варианта по
  [docs/VARIANTS.md](docs/VARIANTS.md). Сохраняй общее ядро и специфику варианта
  при конфликтах. Целиком вариант обратно в `main` не вливай; общее исправление
  из варианта переноси отдельно.
- Сохраняй gameplay/HUD-контракты, scene IDs, переходы, настройки, ввод,
  локализацию и сохранения. Общая база не должна зависеть от ресурсов одного
  варианта. Границы затронутых систем — в
  [docs/ARCHITECTURE_GUARDRAILS.md](docs/ARCHITECTURE_GUARDRAILS.md).
- Сторонние аддоны устанавливаются через `scripts/install_addons.ps1`
  с закрепленными версиями и хешами; их исходники не добавляй в Git.
  `.local`, `.godot`, `builds` и личные настройки MCP остаются локальными.

Для новой игры выбирают нужную ветку и клонируют ее в отдельный репозиторий;
правила синхронизации вариантов там не применяются. Начало работы —
[docs/START_HERE.md](docs/START_HERE.md), подготовка —
[docs/BOOTSTRAP_CHECKLIST.md](docs/BOOTSTRAP_CHECKLIST.md).

## Проверки

Команды и выбор областей — в [docs/TESTING.md](docs/TESTING.md).
По умолчанию smoke проверяет `flow`; запускай только затронутые группы.
Перенос одинаковой общей логики не требует полного прогона во всех вариантах.
Отдельно проверяй вариант при изменении его сцен, ресурсов, настроек или аддонов.
Для документации Godot не запускай. Коммит и ревью сами по себе полного прогона
не требуют; актуальные результаты сохраняют силу.

Импорт, переустановка аддонов, экспорты и ручной чеклист нужны только для
затронутых сценариев. GitHub Actions и другой CI без прямого поручения не добавляй.

## Навигация по коду

Если подключен MCP `codebase-memory`, используй его для поиска неизвестной реализации,
символов и связей между модулями. Для известного файла или точной строки выбирай
прямое чтение либо текстовый поиск. Начинай с компактной выдачи и раскрывай только
нужные участки. Перед использованием графа проверь проект, актуальность индекса
и покрытие затронутых файлов; отсутствие связи в графе не доказывает ее отсутствие
в коде. Перед правкой сверяйся с текущими исходниками. Если индекс недоступен
или неполон, продолжай обычный поиск без остановки задачи.
После переключения ветки проверь актуальность индекса; индекс относится к текущей рабочей папке.

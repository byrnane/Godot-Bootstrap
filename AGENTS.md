# Работа с шаблоном Godot

Этот репозиторий содержит шаблон, а не конкретную игру. Перед изменениями прочитайте
`docs/VARIANTS.md` и проверьте текущую ветку и рабочее дерево.

## Ветки шаблона

Работайте с ветками переключением в основной папке проекта. Дополнительные
worktree и изменения расположения проекта, запуска или привычного рабочего
процесса сначала согласуйте с владельцем и объясните последствия. Временные
чистые клоны для согласованной проверки не заменяют основную рабочую папку.

- `main` — основная ветка разработки и единственный источник общей логики.
  Общие функции, исправления, сервисы, UI-поведение и контракты меняйте здесь.
- `3d`, `2d`, `2d-pixelart` — производные варианты. Они получают изменения
  обычным merge из `main`, независимо друг от друга.
- В вариантах меняйте особенности представления: настройки проекта и рендера,
  мировые сцены, примеры, ресурсы и дополнительные аддоны. Не создавайте в них
  отдельные версии общих сервисов и поведения приложения.
- Сохраняйте общие контракты gameplay/HUD, scene IDs, переходы, настройки,
  ввод, локализацию и сохранения. Общая база не должна обязательно зависеть
  от ресурсов или аддонов одного варианта.
- Если общее исправление потребовалось при работе в варианте, внесите его
  в `main` и перенесите в варианты. Уже сделанное общее исправление переносите
  отдельным коммитом; целиком вариант обратно в `main` не вливайте.
- При конфликтах merge сохраняйте общие изменения `main` и параметры варианта.
  Не отбрасывайте общую логику ради устранения конфликта.
- Перед завершением общего изменения обновите все три варианта. При правках
  запускайте только проверки затронутого поведения; перенос одинакового общего
  кода не требует повторения всего набора на каждом варианте. Проверяйте вариант
  отдельно, если затронуты его сцены, ресурсы, настройки или аддоны.
  Для изменений только документации запуск Godot не нужен.

Архитектурные границы: `docs/ARCHITECTURE_GUARDRAILS.md`.
Порядок обновления и команды: `docs/VARIANTS.md`.

## Новая игра

Для новой игры выбирают `3d`, `2d` или `2d-pixelart` и клонируют выбранную ветку
в отдельный репозиторий. `main` можно использовать, если нужна только общая база.
Начало работы описано в `docs/START_HERE.md` и `docs/BOOTSTRAP_CHECKLIST.md`.

В отдельном репозитории игры правила синхронизации веток шаблона не применяются:
игра развивается самостоятельно и не обязана сохранять набор веток шаблона.
При подготовке игры обновите этот файл под ее задачи и архитектуру.

## Проверки

При доработках запускайте только необходимые проверки по измененному поведению.
Полный прогон (`-Suite all`) допустим только перед финальным коммитом по задаче,
по прямой просьбе владельца или при крайней необходимости. В последнем случае
сначала кратко назовите конкретную причину. Не повторяйте актуальные проверки
без влияющих на результат изменений. Коммит требует отдельного разрешения.

Группы и команды: `docs/TESTING.md`. По умолчанию smoke проверяет только основной
игровой маршрут (`flow`). Импорт, переустановка аддонов, экспорты и ручной чеклист
нужны только для затронутых сценариев, а не после каждой правки.
GitHub Actions в этом проекте не используются: не добавляйте workflows и не
переносите проверки в другой CI без прямого поручения владельца.

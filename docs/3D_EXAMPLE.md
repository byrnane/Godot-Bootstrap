# 3D-пример: служебный блок

Ветка `3d` содержит небольшой законченный шутер в ретро-стиле. Три комнаты,
пять зомби, один пистолет, аптечки и патроны. После зачистки подойдите к шкафу
под надписью EXIT и взаимодействуйте с ним. Смерть и победа позволяют начать
новую попытку или вернуться в меню.

## Запуск и управление

Откройте `project.godot` в Godot 4.7.2 и нажмите F5. В главном меню выберите
«Начать игру». Blender нужен для редактирования ассетов; игра использует GLB
и запускается без Blender, MCP и редакторских аддонов.

Для Windows выбран Mobile renderer с Direct3D 12. После изменения рендерера
уже открытый редактор нужно перезапустить, чтобы F5 использовал новую
конфигурацию. Лимит FPS не установлен; VSync управляется обычными настройками.

| Действие | По умолчанию |
| --- | --- |
| Передвижение | WASD |
| Обзор | Мышь |
| Бег / прыжок | Shift / Space |
| Выстрел / перезарядка | ЛКМ / R |
| Взаимодействие в пределах двух метров | E |
| Первое / третье лицо | V |
| Пауза | F10 |

Клавиши переназначаются в настройках. Ранее сохраненные привязки имеют приоритет;
HUD показывает действующие клавиши. При потере фокуса мышь освобождается;
после возвращения щелкните по игровому полю, чтобы продолжить управление.
В Web щелчок нужен также после начала игры и закрытия паузы: браузер разрешает
захват мыши только из обработчика пользовательского ввода. До захвата мыши
игрок и враги не действуют. Повторных запросов захвата из кадрового цикла нет.

Камера третьего лица сохраняет плечевое смещение, но SpringArm проверяет весь
путь от центра игрока. Стены, дверные проемы, укрытия, пол и потолок сокращают
дистанцию камеры. Положение при свободном обзоре остается прежним.

Здоровье игрока — 100, удар зомби снимает 20. Магазин вмещает 8 патронов,
начальный запас — 24, максимальный — 64. Зомби выдерживает два попадания и
погибает от третьего. Перезарядка занимает две секунды. Аптечка восстанавливает
35 здоровья, коробка дает 16 патронов. При полном ресурсе предмет остается.

## Устройство и замена примера

Вся игровая специфика находится в `features/prototype`. Общие сервисы,
маршрутизация, меню, сохранения и настройки берутся из базы `main`.
Игровая сцена предоставляет обычный контракт `on_enter`, `get_hud_scene`,
`bind_hud`, `unbind_hud`, `on_exit` и сигналы намерений для AppFlow.

`level_stub_a` и `level_stub_b` ведут в один мир; второй ID оставлен совместимым
входом. Комнаты соединены широкими открытыми проемами. Зомби используют
NavigationAgent3D, обнаружение по видимости и ближнюю атаку. Путь учитывает
геометрию и ящики. Коллизия игрока относится к слою 2, врагов — 3,
взаимодействий — 4; слой 1 используется геометрией.

В `SessionContext.game_data` хранится `prototype_version = 1`, состояние игрока,
врагов со стабильными ID, список подобранных предметов, результат и чекпоинт.
Здоровье остается в `SessionContext.player_health`. Сохраняется и обнаружение
игрока врагами: загрузка за укрытием не прекращает уже начатое преследование.
Состояние обновляется во время игры; исходящая сцена не пишет его поверх новой
сессии во время перехода.
Старое сохранение без данных прототипа начинает эпизод с исходного состояния.

Уровень редактируется в `features/levels/level_a.tscn`. Исходный блок-аут Cyclops
сохранен в `authoring/retro_cyclops_blockout.tscn`. Инструмент первоначальной
сборки — `authoring/build_retro_level.gd`: его повторный запуск пересобирает
уровень, поэтому после ручной правки сцены сначала сохраните ее копию.
Экспортированная игровая геометрия не зависит от Cyclops.

## Ассеты и рабочий процесс

Редактируемые исходники и отдельные текстуры находятся в
`art_source/retro_prototype`; игровые GLB — в `assets/models/retro_prototype`.
Исходная модель зомби сохранена отдельным `Zombie_Rigged.original.blend`,
а исходный экспорт — `Zombie_Godot.original.glb`; обе копии сохранены как неизменяемые исходники.
Доработки и дополнительные клипы находятся в `Zombie_Rigged.prototype.blend`.
Остальные модели собраны в `Retro_Prototype.blend`.

Для обычной правки откройте нужный `.blend`, измените модель или клип и
переэкспортируйте соответствующую коллекцию. Не запускайте первоначальное
создание поверх отредактированного исходника. Подробности и имена клипов:
[карточка ассетов](../art_source/retro_prototype/ASSETS.md).
Практические результаты работы инструментов: [3D_WORKFLOW.md](3D_WORKFLOW.md).

## Проверки и сборка

`flow` через штатный изолированный wrapper включает вариантные проверки боя,
камер, подбора, навигации, победы, рестарта и сохранений. `localization` проверяет
RU/EN. Headless-проверки не заменяют просмотр моделей и графическое прохождение.

```powershell
$env:GAME_TEMPLATE_VARIANT = '3d'
pwsh -File scripts/run_smoke.ps1 -Headless -Suite flow
pwsh -File scripts/run_smoke.ps1 -Headless -Suite localization
Remove-Item Env:GAME_TEMPLATE_VARIANT
```

Windows собирается штатным пресетом `Windows`: `builds/3D/windows/GameTemplate.exe`.
Web собирается пресетом `Web`: `builds/3D/web/index.html`. Каталог сборок исключен
из Git. Для Web нужен локальный HTTP-сервер или игровой хостинг; открытие HTML
как файла не подходит.

Windows и Web приняты владельцем 28 октября 2026 по согласованному короткому
маршруту с клавиатурой и мышью. Более долгая загрузка уровня в Web отмечена как
наблюдение и приемке не мешает. Текущий результат и история проверок описаны в
[3D_WORKFLOW.md](3D_WORKFLOW.md#ручная-приемка--28-октября-2026).

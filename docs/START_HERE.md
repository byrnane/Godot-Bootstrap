# Начало нового проекта

База: Godot **4.7.2**, GDScript, Compatibility, встроенная физика Jolt.
После клонирования сначала установите закрепленные аддоны одной командой в PowerShell 7:

```powershell
pwsh -File scripts/install_addons.ps1
```

Скрипт скачивает релизные архивы Godot AI и Cyclops, проверяет SHA-256 и устанавливает их в игнорируемые папки `addons`. Уже установленные файлы не перезаписываются. Версии и адреса закреплены в `scripts/addons.lock.json`. Собственный `addons/template_export` хранится в Git.

Откройте `project.godot` и нажмите **F6** на `main/main.tscn` либо **F5** для всего проекта.
Меню, HUD, пауза, настройки, RU/EN, ребинд и сохранения уже подключены.
Пауза по умолчанию — **F10**, назад/закрыть модальное окно — **Escape**. Существующие пользовательские привязки сохраняются.

## Своя игра

1. Скопируйте шаблон в отдельную папку. Папки `.local`, `.godot`, `builds` и старый `.git` не переносите.
2. Поменяйте название в `project.godot`, иконку и данные Windows-пресета.
3. Подставьте свои сцены в `core/registry/scenes.gd` и замените демонстрационный HUD.
4. Добавляйте игровые данные в `SessionContext` и `SaveData`, тексты — в `translations/UI.csv`.
5. При переименовании игры учитывайте новый каталог `user://`: старые сохранения автоматически туда не переезжают.

По умолчанию реестр использует `gameplay_3d.tscn`, `level_3d_a.tscn`, `level_3d_b.tscn`.
Это технический пример: свет, камера, ящик с материалом и падающий куб. Никакого контроллера персонажа и PS1-эффектов.

Для плоского примера замените **только три пути** в реестре:

| ID | Плоский пример |
| --- | --- |
| `GAMEPLAY` | `res://features/gameplay/gameplay_stub.tscn` |
| `LEVEL_STUB_A` | `res://features/levels/level_stub_a.tscn` |
| `LEVEL_STUB_B` | `res://features/levels/level_stub_b.tscn` |

Идентификаторы и формат сохранений остаются прежними. Общий контроллер работает с `Node`, HUD — через существующие сигналы.

## Модель, текстура и материал

- Исходник: `art_source/demo_crate/demo_crate.blend`.
- Текстура: соседний `crate_base_color.png`, 64×64. Каждая грань ящика использует весь квадрат через UV.
- Материал Blender: Image Texture → Base Color узла Principled BSDF, Roughness = 0.9.
- Ресурс игры: `assets/models/demo_crate.glb`. Godot извлекает встроенную текстуру рядом с GLB при импорте.
- Игровая обертка: `features/props/demo_crate.tscn`. Коллизия хранится здесь, отдельно от импортированной модели.

Откройте `.blend`, выберите `Crate`, измените модель или текстуру. Сохраните `.blend` и изображение.
В **File → Export → glTF 2.0** выберите **GLB**, включите **Selected Objects** и перезапишите `assets/models/demo_crate.glb`.
Возврат в Godot запускает переимпорт. Игровая коллизия при этом сохраняется; если размеры изменились, поправьте ее вручную.
Масштаб примера: 1 единица = 1 метр. Исходники находятся под `.gdignore` и в сборку не попадают.

Для такой стилизации хватит Blender: UV Editing и Texture Paint. Плоские PNG также можно рисовать в привычном графическом редакторе.
Произвольные процедурные узлы Blender через GLB не переносятся: для игры используйте простые материалы с изображениями или запекайте результат в текстуру.
Скрипт `create_crate.py` рядом с исходником воспроизводит именно пример; для обычного редактирования запускать его не нужно.

Godot AI включен в **Project Settings → Plugins**. Откройте проект в редакторе, дождитесь **Server connected** в доке.
Подключение Codex хранится в локальном `.codex/config.toml` и использует `godot-ai==4.3.0 attach`.
После копирования проекта создайте локальное подключение для новой папки. Старый отключенный MCP не включайте параллельно.
Дока проверяет глобальную конфигурацию Codex, поэтому ее строка Codex может показывать Not configured при рабочем проектном подключении.
Редактор должен быть открыт для работы со сценами; экспортированные игры MCP не содержат.

В Blender включен аддон **Interface: Blender MCP**; соединение локальное, порт **9876**.
Панель **N → Blender MCP** позволяет запустить/остановить соединение. Safe mode включен в конфигурации MCP-клиента.
В Codex установлен один плагин **MCP for Blender** с просмотром сцены: отдельный дублирующий MCP не нужен.
После изменения конфигурации может понадобиться обновить подключения Codex или перезапустить приложение.
Safe mode ограничивает отправляемый Python, но не превращает сам Blender в изолированную среду.

Cyclops — дополнительный редактор блоков. Исходная комната: `authoring/cyclops_room.tscn`.
Ее экспорт в штатные MeshInstance3D / StaticBody3D / CollisionShape3D: `features/levels/blockout_room.tscn`.
Для новых набросков используйте Cyclops и **Export as Godot Scene**. Основные демонстрационные уровни от Cyclops не зависят.

## Сборки

В **Project → Export** есть **Windows** (x86_64) и **Web** (без потоков и GDExtension).
Совпадающие export templates установлены в обычном профиле редактора. Результаты — в `builds/windows` и `builds/web`.

```powershell
New-Item -ItemType Directory -Force builds/windows, builds/web
godot --headless --path . --export-release Windows
godot --headless --path . --export-release Web
```

На Windows проверьте команду `godot --version` в обычном терминале.
Для Web поднимите локальный HTTP-сервер из папки сборки; открытие `index.html` через `file://` не подходит.
Например: `python -m http.server 8067 --bind 127.0.0.1 --directory builds/web`.

Сейвы Web хранятся в браузере для текущего origin. Перенос на другой адрес/порт, приватный режим и очистка данных браузера влияют на их доступность.
Звук разрешается после первого взаимодействия. Полный экран включайте нажатием чекбокса в настройках; автоматически при загрузке он не запрашивается.
Кнопка выхода и настройка автосейва при выходе в Web скрыты. Используйте обычные сейвы, таймер и чекпоинты: закрытие вкладки не гарантирует запись.

В проекте отключено `editor/export/convert_text_resources_to_binary`: на этом ПК бинарная конвертация вложенных UI-сцен приводила к потере `%`-ссылок в обеих сборках.
Текстовые ресурсы экспортируются штатно; это не изменение формата сохранений.
Редакторские аддоны и их autoload исключаются из экспортированных игр.

## Короткая проверка

```powershell
pwsh -File scripts/run_smoke.ps1 -Headless
```

Нужен **PowerShell 7**. Скрипт создает отдельный профиль дочернего процесса в `.local/smoke/<run-id>`.
Он требует PASS текущего запуска, код 0 и отсутствие SCRIPT ERROR/ERROR; настоящие сохранения владельца не используются.
Прямой запуск smoke-сцены из редактора намеренно запрещен без изоляции.
После собственных изменений проверьте реальный маршрут меню → игра → пауза/настройки → сохранение → меню → продолжить, затем Windows/Web.
Новый тестовый фреймворк не добавлен.

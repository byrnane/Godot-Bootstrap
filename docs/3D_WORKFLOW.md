# Рабочий процесс 3D-прототипа

Этот документ фиксирует фактический опыт создания примера в ветке `3d`.
Общие правила проекта и универсальный навык 3D-ассетов здесь не дублируются.

## Проверенное окружение

- Godot 4.7.2 Steam, Jolt. Первоначальные проверки проводились с Compatibility/OpenGL.
  После сбоя обычного запуска ветка `3d` переведена на Mobile с Direct3D 12
  для Windows. Владелец подтвердил нормальную работу редакторского запуска
  и обновленного Windows EXE; Web еще не принят.
- Blender 5.2.3 LTS, MCP for Blender 1.8, протокол 14; safe mode включен.
- Работающий редакторский Godot AI 4.3.1. В общем установщике проекта остается
  закрепленная 4.3.0: локальное обновление владельца не меняет общий lock.
- Cyclops 1.5.1 с существующим проектным патчем; используется для исходного
  блок-аута, экспорт игры содержит статичную геометрию.

### Подключения

Состояние «приложение запущено» не подтверждает связь с MCP. В Blender нужен
запущенный сервер панели MCP for Blender; текущий порт — 9876. В этой сессии
Refresh Local и перезапуск не сделали установленный файл видимым в Preferences.
Штатная установка существующего файла через Install from Disk позволила
включить аддон и подключиться. Причина первоначальной невидимости не установлена.

Godot показывал Server connected, но чат был подключен к другому серверу:
редактор использовал 8001/9501, старый клиент — 8000/9500. Локальный конфиг
согласован с сервером 4.3.1. Уже запущенное MCP-подключение чата не перечитывает
конфиг автоматически; для текущей работы применялся официальный MCP SDK со
штатным `godot-ai attach`. Для новой сессии достаточно обновленного локального
конфига. Порты и личные конфиги не нужно переносить в другую игру вслепую.

## Blender → GLB → Godot

1. Проверить текущий `.blend`, сцены и несохраненные изменения; сохранить
   восстанавливаемую копию перед существенной правкой.
2. Подготовить модель, UV, материалы, риг и именованные клипы. Исходную модель
   зомби сохранить отдельно; работать с проектной копией.
3. Осмотреть модель и воспроизведение клипов в Blender. Сверить режимы вращения
   костей с существующими ключами: исходные клипы зомби используют Quaternion.
4. Экспортировать нужную коллекцию, только активную сцену, с rest bindpose.
5. В Godot импортировать GLB и проверить реальный материал, масштаб, ориентацию,
   имена клипов и работу контроллера. Сохранять игровую коллизию и поведение
   в собственной сцене, поверх импортируемой модели.
6. После следующей правки повторить только экспорт нужного ассета и проверить
   сохранность настроек его игрового окружения.

Контрольная итерация: красная мушка добавлена в исходник пистолета, затем
переэкспортирована его коллекция. GLB изменился; контрольные суммы уровня
и сцены игрока остались прежними. Изменение принято после импорта в движок.

### Найденные особенности

- Safe mode запрещает `runpy`, Python-файловые API и lambda. Для MCP используется
  напрямую передаваемый `mcp_assets.py`, предварительно проверенный настоящим
  AST-валидатором сервера. Каталоги и проверка наличия файлов выполняются отдельно.
- Открытие `.blend` и дальнейший экспорт лучше разделять на два MCP-вызова:
  контекст `selected_objects` может отсутствовать до следующего цикла событий.
- `use_selection` не исключает выбранные объекты других сцен. Нужен также
  `use_active_scene`, иначе в экспорт может попасть посторонний куб.
- После sampling экспортер может оставлять последние pose channels. Экспорт
  сохраняет и восстанавливает позу, Action/slot, NLA, кадр, выделение и видимость.
- Переключение костей Quaternion → Euler ломает воспроизведение исходных клипов.
  Добавляемые клипы используют существующий режим; оригинальные Actions сохранены.
- Режим NLA_TRACKS использует имена треков. Для исходных Walk/Attack/Bite нужны
  отдельные именованные треки, даже если они уже стоят в общей NLA-последовательности.
- В новых GLB выбран импорт встроенных изображений как Embedded Uncompressed.
  Это устранило зависимость от извлеченных PNG и предупреждения устаревших UID.
  Отдельные редактируемые PNG сохранены рядом с `.blend`.
- SpringArm управляет положением дочерней камеры. Для плечевого обзора он
  начинается в центре игрока и направлен по диагонали к нужной позиции камеры;
  камера компенсирует его поворот. Боковой сдвиг самого начала SpringArm
  оставлял его за стеной и позволял смотреть сквозь нее. Потолок имеет коллизию;
  ограниченный объем navigation bake ее не включает. Смещение пути
  NavigationAgent учитывает высоту voxel bake.
- Временные ConvexVolume содержат сильные обратные ссылки. Первоначальный
  экспортер блок-аута освобождает собственные временные графы после упаковки сцен.

## Границы результата

Прототип использует клавиатуру и мышь, один тип врага и одно оружие.
Нативное прохождение и Windows-экспорт проверяются отдельно от headless smoke.
Физический геймпад не входит в приемку этого примера. Для Web проверен базовый
сценарий в Chrome; полный маршрут, сохранения IndexedDB после перезапуска
и размещение на игровом хостинге еще не приняты. Целевой Web-профиль на 60 FPS
обсужден, но ограничение не применялось и не считается гарантией исправления.

### Приемка 25 октября 2026

**Последующее уточнение:** после первоначальных проверок владелец обнаружил
тяжелые тормоза EXE и редакторского запуска с Compatibility/OpenGL. После
перехода на Mobile/Direct3D 12 он подтвердил нормальную работу обоих запусков.
Приведенные ниже внутренние FPS первоначального пакета не доказывают плавность
изображения на мониторе. См. [факты и решение](3D_PERFORMANCE_INVESTIGATION.md).

- Штатные `flow` с вариантными проверками и `localization` завершились PASS.
  Проверены препятствия и попадания в упор, обе камеры, боезапас, предметы,
  урон, навигация через проем, смерть, победа, рестарт и восстановление мира.
- Графическое прохождение первоначального игрового пакета Compatibility завершило
  весь маршрут в FPS и TPS: пять врагов уничтожены, патроны подобраны, выход
  активирован; в обоих случаях осталось 80 здоровья. Управление подавалось
  обычными событиями ввода, без телепортации и восстановления здоровья.
- Пакет проверялся редакторским исполняемым Godot через `--main-pack`:
  это подтверждает ресурсы экспортированной игры, но не заменяет приемку
  обычного release EXE. В пакете нет сцены исходного блок-аута и зависимости
  от редакторских инструментов.
- В графическом запуске пакета проверены пауза, настройки, возврат управления,
  RU HUD при 1280×720 и 1024×576, а также звук через WASAPI. Потеря фокуса
  проверена уведомлениями приложения; реальный Alt-Tab остается непроверенным.
- Независимое стандартное ревью кода и соответствия задаче выявило два дефекта:
  исходящая сцена могла перезаписать данные новой сессии, а луч выстрела неверно
  обрабатывал близкое препятствие. Оба исправлены и адресно перепроверены.

Полный маршрут через обычное окно EXE агент не прошел: запрос разрешения
Computer Use истек по таймауту. Затем владелец подтвердил нормальную работу
обновленных редакторского запуска и EXE с Direct3D 12. Отдельно остаются
неподтвержденными полный маршрут новой сборки и реальный Alt-Tab, а также Web.

### Аудит и исправления 25 октября 2026

Проведено полное ревью: код, соответствие всему поручению и качество решения.
Этапы 1–2 и этап 3 проверили два независимых агента; после исправлений они
адресно проверили затронутые места. Дополнительного полного круга не было.

Исправлены подтвержденные дефекты:

- Камера проходила через боковую стену из-за смещенного начала SpringArm
  и через потолок без коллизии. Плечевой ракурс сохранен; проверяется весь
  диагональный путь от игрока, потолок участвует в столкновениях.
- Позиции около `z=4.12` и `z=-29.12` достижимы капсулой игрока, но загрузчик
  их отбрасывал. Допустимые границы согласованы с геометрией.
- Зомби теряли состояние преследования при загрузке за укрытием. Поле `alerted`
  теперь входит в snapshot; старые сохранения без него остаются совместимыми.
- Web запрашивал Pointer Lock каждый кадр вне пользовательского события.
  Захват перенесен в обработчик клика, отпускание и состояние отслеживаются
  в кадре. Враги ждут вместе с игроком, пока управление освобождено.
- Текстовый значок паузы не отображался в Web без системного fallback-шрифта.
  Используется существующая SVG-иконка проекта. Подсказка возврата управления
  скрывается после смерти или победы.
- Общий smoke требовал Compatibility от уже переведенной на Mobile ветки.
  Проверка исправлена в `main` и перенесена во все три варианта.

## Замечания к универсальному навыку

Глобальные скиллы не изменялись. Полезные уточнения к навыку 3D-ассетов:
ранняя проверка совместимости вращений, явная изоляция экспортируемой сцены,
восстановление состояния после экспорта и проверка safe-mode кода до исполнения.

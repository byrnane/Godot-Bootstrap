# Рабочий процесс 3D-прототипа

Ветка `3d` использует редактируемые исходники Blender, игровые GLB и сцены
Godot. Запуск, управление и устройство примера: [3D_EXAMPLE.md](3D_EXAMPLE.md).
Имена ассетов, клипов и операции экспорта:
[карточка ассетов](../art_source/retro_prototype/ASSETS.md).

## Ручная приемка — 28 октября 2026

Windows и Web приняты по короткому маршруту: запуск, звук, управление,
плавность и основные игровые переходы. Более долгая загрузка уровня в Web
остается наблюдением; ее длительность не измерялась, причина не исследовалась.

Приемка не охватывает полное прохождение, реальный Alt-Tab и отдельную проверку
сохранений IndexedDB после перезапуска. Физический геймпад не проверялся:
пример использует клавиатуру и мышь.

## Окружение

- Godot 4.7.2, Jolt. Windows использует Mobile с Direct3D 12;
  Web — Compatibility/WebGL 2 без потоков. Выбор renderer описан
  в [технической заметке](3D_PERFORMANCE_INVESTIGATION.md).
- Исходники и экспорт проверены в Blender 5.2.3 LTS.
- Для автоматизации Blender использовался MCP for Blender 1.8, протокол 14,
  с включенным safe mode. Для обычного редактирования и экспорта MCP не нужен.
- Godot AI и Cyclops устанавливаются командой
  `pwsh -File scripts/install_addons.ps1`; версии закреплены в
  `scripts/addons.lock.json`. Cyclops 1.5.1 с проектным патчем используется
  для исходного блок-аута. Игра содержит статичную геометрию и от него не зависит.

## Blender → GLB → Godot

1. Проверьте текущий `.blend`, сцены и несохраненные изменения. Перед существенной
   правкой сохраните восстанавливаемую копию.
2. Подготовьте модель, UV, материалы, риг и именованные клипы. Исходную модель
   зомби храните отдельно; редактируйте проектную копию.
3. Осмотрите модель и воспроизведение клипов в Blender. Сверьте режимы вращения
   костей с существующими ключами: исходные клипы зомби используют Quaternion.
4. Экспортируйте нужную коллекцию, только активную сцену, с rest bindpose.
5. В Godot импортируйте GLB и проверьте материал, масштаб, ориентацию,
   имена клипов и работу контроллера. Игровую коллизию и поведение храните
   в собственной сцене поверх импортируемой модели.
6. После следующей правки повторите экспорт только нужного ассета и проверьте
   сохранность настроек его игрового окружения.

При контрольном переэкспорте изменение красной мушки пистолета прошло цикл
`.blend` → GLB → Godot; сцены игрока и уровня остались прежними.

### Особенности экспорта и импорта

- Safe mode запрещает `runpy`, Python-файловые API и lambda. MCP использует текст
  `mcp_assets.py`, проверенный AST-валидатором сервера. Проверка наличия файлов
  и подготовка каталогов выполняются вне Blender. Контракт вызовов описан
  в [разделе автоматизации](../art_source/retro_prototype/ASSETS.md#автоматизация-через-mcp).
- Открытие `.blend` и экспорт разделяются на два MCP-вызова:
  контекст `selected_objects` может отсутствовать до следующего цикла событий.
- `use_selection` не исключает выбранные объекты других сцен. Нужен также
  `use_active_scene`, иначе в экспорт может попасть посторонний куб.
- После sampling экспортер может оставлять последние pose channels. Экспорт
  сохраняет и восстанавливает позу, Action/slot, NLA, кадр, выделение и видимость.
- Переключение костей Quaternion → Euler ломает воспроизведение исходных клипов.
  Добавляемые клипы используют существующий режим; оригинальные Actions сохраняются.
- NLA_TRACKS использует имена треков. Для исходных Walk/Attack/Bite нужны
  отдельные именованные треки, даже если они уже стоят в общей NLA-последовательности.
- GLB использует импорт встроенных изображений как Embedded Uncompressed.
  Это устраняет зависимость от извлеченных PNG и предупреждения устаревших UID.
  Отдельные редактируемые PNG остаются рядом с `.blend`.
- Временные ConvexVolume содержат сильные обратные ссылки. Экспортер блок-аута
  освобождает собственные временные графы после упаковки сцен.

## Аудит и исправления 25 октября 2026

- SpringArm начинается в центре игрока и направлен по диагонали к плечевой
  позиции камеры; камера компенсирует его поворот. Проверяется весь путь,
  включая стены и потолок. Ограниченный объем navigation bake не включает потолок;
  смещение пути NavigationAgent учитывает высоту voxel bake.
- Границы загрузки позиции учитывают достижимые капсулой игрока точки около
  `z=4.12` и `z=-29.12`.
- Состояние преследования зомби `alerted` входит в snapshot;
  старые сохранения без него остаются совместимыми.
- Исходящая сцена не перезаписывает данные новой сессии. Луч выстрела учитывает
  близкие препятствия.
- Web запрашивает Pointer Lock из обработчика клика. При освобожденном управлении
  игрок и враги ждут; захват не запрашивается каждый кадр.
- Значок паузы использует SVG проекта без зависимости от системного fallback-шрифта.

## Проверки и сборка

`flow` включает вариантные проверки боя, камер, предметов, навигации, победы,
рестарта и сохранений. `localization` проверяет RU/EN. Актуальные прогоны этих
групп прошли; редакторский маршрут Mobile/D3D12 завершен в обеих камерах.
Windows/Web release собраны без ошибок и утечек. Эти результаты дополняют
ручную приемку в указанном выше объеме.

```powershell
$env:GAME_TEMPLATE_VARIANT = '3d'
pwsh -File scripts/run_smoke.ps1 -Headless -Suite flow
pwsh -File scripts/run_smoke.ps1 -Headless -Suite localization
Remove-Item Env:GAME_TEMPLATE_VARIANT
```

Штатный wrapper изолирует пользовательские данные. Порядок выборочных проверок:
[TESTING.md](TESTING.md). Headless smoke не заменяет просмотр моделей,
прохождение и запуск экспортированной игры. Проверка пакета редакторским Godot
через `--main-pack` также не заменяет обычный release EXE.

Windows-пресет создает `builds/3D/windows/GameTemplate.exe`,
Web-пресет — `builds/3D/web/index.html`. Для Web нужен HTTP-сервер или игровой
хостинг. Лимит FPS не установлен; VSync управляется настройками игры.

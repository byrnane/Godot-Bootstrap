# Локальные проверки

Выбирайте группы по измененному поведению. Если затронуты несколько областей,
проверяйте их вместе; `all` нужен для проверки всей общей инфраструктуры.
Используйте актуальные результаты для неизменившихся сценариев.

```powershell
pwsh -File scripts/run_smoke.ps1 -Headless -Suite flow
```

| Группа | Когда нужна |
| --- | --- |
| `flow` (по умолчанию) | Меню, игра, HUD, уровни, пауза/настройки, сохранение и продолжение; конфигурация варианта при заданной `GAME_TEMPLATE_VARIANT` |
| `ui` | Компоненты, координатные клики через UiShell, колонки биндингов и отступ скролла, отмена черновика настроек, создание первого слота |
| `persistence` | Данные и миграции, восстановление backup, ввод, настройки, ошибки записи и Retry при выходе |
| `transitions` | Очередь переходов, неизвестная сцена, переопределение стартовой сцены, пауза во время загрузки и модалки |
| `audio` | Аудиошины, UI-звук и музыка |
| `localization` | Покрытие ключей и переключение языка |
| `all` | Все группы по одному разу |

`transitions` также проверяет нестандартные root IDs из конфигурации и параметров
запуска: intent-сигналы меню/gameplay, паузу, рестарт, сохранение, загрузку и возврат.
`ui` проверяет очередь feedback при запросах во время закрытия, повторных сигналах
и отмене всей очереди, включая новый диалог из callback. Подмена тестовых сцен
меняет только кеш ресурсов изолированного процесса, без записи сцен на диск.

`ui` также проверяет переходы мышь/Tab/стрелки/синтетический D-pad, редактирование
текста, удержание кнопки и перетаскивание слайдера. Геометрия debug overlay и
состояний кнопки паузы проверяется при 1280×720, 1720×720, 1280×960 и 640×360.
`audio` проверяет Web-настройку Stream и аудиограф; Dummy audio не подтверждает
слышимость. Для Web нужен отдельный запуск после пользовательского клика.

Для изменений только документации запуск Godot не нужен.

Визуальная проверка UI: F6 для `shared/ui/catalog/ui_catalog.tscn`, затем обычный
запуск `main/main.tscn` и затронутые экраны. Проверьте RU/EN, мышь, клавиатурный
фокус и целевой размер окна. Headless `ui` не подтверждает внешний вид;
эмулированные Joypad-события не заменяют физический геймпад.
Автоматизированные графические проверки запускайте с `--audio-driver Dummy`,
чтобы не включать звук; аудиопроверку проводите отдельно.
Для штатного wrapper используйте `pwsh -File scripts/run_smoke.ps1 -Suite ui -DummyAudio`.

Полный локальный прогон:

```powershell
pwsh -File scripts/run_smoke.ps1 -Headless -Suite all
```

Используйте PowerShell 7 и штатный wrapper: он изолирует пользовательские данные
в `.local/smoke/<run-id>`. Запускайте тестовые сцены через него, сохраняя реальные
настройки, привязки и сохранения игры.
Успех: `PASS` текущего запуска, код выхода 0 и отсутствие `SCRIPT ERROR`/`ERROR`
и предупреждений об утечках ObjectDB. Функциональный PASS при утечке не принимается.
Журналы `stdout.log`, `stderr.log` и файл `phase0_smoke_result.txt` находятся
в каталоге запуска. Проверяйте первое сообщение об ошибке; после исправления
повторяйте только затронутую группу.

Для диагностики завершения добавьте `-VerboseGodot`: движок выведет подробности
загрузки и список оставшихся объектов. Wrapper проверяет ошибки в обоих потоках
вывода. Все регрессии сохранений работают только в изолированном профиле wrapper.

Устанавливайте аддоны и импортируйте ресурсы только при необходимости подготовки
окружения. Экспорт Windows/Web и ручные проверки выполняйте только для изменений,
которые требуют проверки экспорта, платформы или визуального поведения.
Обновление общей логики не требует повторения всех групп в каждом варианте:
отдельно проверяйте варианты, чье представление или настройки затронуты.

При изменении установщика патчей аддонов запустите
`pwsh -File scripts/test_addon_patches.ps1`. Проверка создает изолированный
репозиторий в `.local/addon-patch-tests/`, не скачивает аддоны и проверяет
применение, повторный запуск и сохранность конфликтующей локальной правки.
